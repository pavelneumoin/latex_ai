# Неумошка: локальный запуск и проверка

Рабочая папка: `D:\Sites\latex_ai\frontend`.
Адрес: http://localhost:3010 . Сервер слушает только `127.0.0.1`, доступа из интернета нет.

## Каталог после ночной доработки 7 октября

Для изолированной проверки используется `http://localhost:3015`, администратор —
`/admin/catalog`. Его отдельный вход сохранён владельцу на рабочем столе в файле
«Неумошка — администратор библиотеки.txt». Школьный аккаунт этим не меняется.
Чтобы запустить готовую сборку на проверочном порту:

```powershell
$env:PORT='3015'
$env:NEXTAUTH_URL='http://localhost:3015'
$env:NEXT_PUBLIC_SITE_URL='http://localhost:3015'
npm start
```

Перед первым запуском этой версии на существующей установке сохранить согласованную
копию SQLite, выполнить `npm run db:migrate:deploy`, `npm run db:generate`, затем
сборку. Миграция `20261007004000_catalog_kits` добавляет только поля Product и не
сбрасывает данные. На этом компьютере миграция уже применена; резервная копия
находится вне репозитория, в `school-private/catalog-20261007/library-before.sqlite`.

В каталоге и кабинете теперь одна кнопка на весь комплект Яндекс Диска. Ссылок на
полные комплекты пока нет: добавить их в редакторе, затем проверить содержимое Диска.
Администратор видит черновики и получает полный доступ без подписки. Обычный
пользователь сохраняет прежние ограничения. Старый API отдельных файлов сохранён
для совместимости и тоже проверяет роль/подписку; в новом интерфейсе таких кнопок нет.

`node scripts/verify-catalog-admin.mjs` проверяет локальный сервер 3015 с временными
аккаунтами/комплектом, удаляет только свои данные и не делает реальный платёж.
Проверяется ответ-перенаправление на Диск, без скачивания полного архива. Это не
подтверждение содержимого будущих пользовательских комплектов.

Полный отчёт и план: `../docs/CATALOG-NIGHT-2026-10-07.md`,
`../docs/TEACHER-LIBRARY-ROADMAP.md`.

## Запуск

```powershell
cd D:\Sites\latex_ai\frontend
.\scripts\start-local.ps1
```

В текущей установке зависимости, база и два комплекта уже подготовлены.
Файлы `.env`, `.env.local`, `prisma/dev.db`, папка `storage` не должны попадать в Git.
Секреты и файлы материалов не публиковать вместе с кодом.

При новой установке: `npm ci`, заполнить `.env.local` по `.env.example`, задать
`DATABASE_URL="file:./dev.db"` также в `.env`, выполнить `npm run db:migrate:deploy`,
затем `npm run db:seed`. На Windows, если Prisma возвращает пустую ошибку engine
для отсутствующего SQLite-файла, создать пустой `prisma/dev.db` и повторить миграции.
Не использовать `db:reset` для базы с нужными аккаунтами.

## Подключение VK ID

1. В обычном браузере открыть https://id.vk.com/business/go и войти в свой VK.
2. Создать приложение для Web с названием «Неумошка».
3. Настроить разрешённый адрес возврата под реальный адрес сайта.
   Для текущего локального сервера код ожидает строго
   `http://localhost:3010/api/auth/callback/vkid`.
   Возможность принять HTTP localhost зависит от настроек кабинета VK; если кабинет
   отклоняет адрес, нужен отдельный тестовый HTTPS-домен. Не указывать выдуманный URL.
4. Числовой ID приложения записать в `VK_ID_CLIENT_ID` в `.env.local`.
   Если кабинет требует серверный секрет, записать его в `VK_ID_CLIENT_SECRET`
   в том же файле. Секрет не отправлять в чат и не коммитить.
5. Перезапустить сервер. Кнопка VK ID станет доступна.
6. Проверить настоящий вход, создание аккаунта, выход и повторный вход.
   Сейчас без APP_ID эти проверки не выполнены; проверены только обработчики и
   проверки state/PKCE на тестовых данных.

При публикации `NEXTAUTH_URL`, `NEXT_PUBLIC_SITE_URL` и разрешённый callback VK
должны использовать один выбранный HTTPS-домен. В локальной проверке открывать
`localhost`, не смешивать его с `127.0.0.1` — cookies привязаны к адресу.

Официальный SDK и описание протокола:
https://github.com/VKCOM/vkid-web-sdk

## Проверки

```powershell
npm run typecheck
npm test
node scripts/verify-local-flow.mjs
```

Последняя команда требует работающий локальный сервер с `PAYMENTS_PROVIDER=mock`.
Она создаёт временного пользователя, проверяет разовый платёж 499 ₽, запрет годового
тарифа, сохранение подписки, скачивание PDF в новой сессии, истечение срока,
повторный webhook и закрытые API. В конце удаляет только созданный тестовый аккаунт.

`npm run build` запускать при остановленном dev-сервере: они используют одну `.next`.
